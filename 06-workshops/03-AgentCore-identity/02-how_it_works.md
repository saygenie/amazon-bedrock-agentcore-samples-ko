# Bedrock AgentCore Identity 작동 방식

## 소개

AgentCore Identity는 보안이나 사용자 경험을 저해하지 않으면서 에이전트가 여러 서비스의 사용자별 데이터에 안전하게 액세스하도록 지원해야 하는 AI 에이전트 배포의 근본적인 과제를 해결합니다. 기존 방식은 세분화된 제어 없이 광범위한 액세스 자격 증명을 사용하거나, 서비스 통합마다 명시적인 사용자 동의를 요구하여 사용자 경험을 저해합니다. AgentCore Identity는 제로 트러스트 보안 원칙과 위임 기반 인증을 구현하는 포괄적인 워크플로를 통해 이 문제를 해결합니다.

이 서비스는 가장이 아닌 위임 원칙에 따라 작동합니다. 에이전트가 사용자 자격 증명을 직접 사용하는 대신, 검증 가능한 사용자 컨텍스트를 포함한 상태로 에이전트 자신을 인증합니다. 이 방식은 세분화된 액세스 제어, 포괄적인 감사 추적, 사용자 액세스와 별개로 에이전트 액세스를 취소하는 기능을 제공합니다. 이 워크플로는 여러 신뢰 도메인에 걸친 복잡한 인증과 권한 부여를 조정하면서 개발자에게는 간단한 인터페이스를 제공합니다.

AgentCore Identity는 적절한 보안 경계를 유지하면서 에이전트가 리소스에 액세스할 수 있도록 안전한 인증 메커니즘을 제공합니다. 이를 통해 서비스는 적절한 권한 부여 결정을 내릴 수 있으며, 하나의 워크플로에서 내부 캘린더 시스템과 Google Calendar 같은 외부 서비스에 모두 액세스할 수 있는 서비스 간 에이전트와 같은 고급 사용 사례를 지원합니다.

다음 다이어그램은 사용자, 애플리케이션, 에이전트, AWS 리소스 및 서드 파티 서비스가 안전하게 상호 작용하는 전체 AgentCore Identity 워크플로를 보여 줍니다.

AgentCore Identity 워크플로는 다음 단계로 구성됩니다.

**사용자가 OAuth/OIDC로 로그인하고 애플리케이션에 토큰 전달** — 사용자는 조직의 기존 Identity Provider(예: Auth0, Cognito 또는 기타 OIDC 호환 시스템)를 통해 인증하고 액세스 토큰이나 ID 토큰을 받습니다. 이 토큰에는 사용자의 ID 정보와 승인된 scope가 포함되어 전체 워크플로의 사용자 ID 컨텍스트를 설정합니다. 애플리케이션은 이 토큰을 받아 에이전트 요청에 권한을 부여하는 데 사용합니다.

**사용자용 애플리케이션이 사용자 로그인 처리** — 애플리케이션은 사용자의 인증 토큰을 검증하고 안전한 세션을 설정합니다. 이 단계에서는 사용자가 올바르게 인증되었으며 AI 에이전트 호출 기능을 포함한 애플리케이션 기능에 액세스할 권한이 있는지 확인합니다. 애플리케이션은 개인화와 액세스 제어를 위해 토큰에서 사용자 ID 정보를 추출할 수도 있습니다.

**사용자가 AI 에이전트의 리소스 액세스 요청** — 사용자가 에이전트와의 상호 작용을 시작하면 애플리케이션은 사용자를 대신하여 AI 에이전트를 호출하도록 요청합니다. 이 요청에는 사용자의 인증 토큰과 에이전트가 수행해야 할 작업에 필요한 컨텍스트가 포함됩니다. 애플리케이션은 프록시 역할을 하며, 사용자의 ID 컨텍스트를 유지하면서 인증된 요청을 에이전트 인프라로 전달합니다.

**사용자용 애플리케이션이 사용자 토큰과 함께 에이전트 서비스에 요청** — Bedrock AgentCore 서비스는 요청을 수신하고 구성된 권한 부여 정책에 따라 사용자 토큰을 검증합니다. 이 검증에는 토큰의 서명, 만료 시간, 발급자, 대상 및 필수 scope 확인이 포함됩니다. 서비스는 사용자가 특정 에이전트를 호출하는 데 필요한 권한이 있고 요청이 모든 보안 요구 사항을 충족하는지 확인한 후 처리를 계속합니다.

**Bedrock AgentCore가 Agent Credential Provider에 워크로드 액세스 토큰 요청** — 에이전트 서비스는 워크로드 액세스 토큰을 얻기 위해 토큰 교환 프로세스를 시작합니다. 에이전트 서비스는 사용자의 토큰을 AgentCore Identity의 토큰 교환 API에 제출합니다. 이 요청은 IAM 자격 증명으로 권한을 부여받습니다. 이를 통해 신뢰 체인을 유지하고 권한 부여 결정을 지원하면서 다운스트림 리소스에 안전하고 감사 가능한 방식으로 액세스할 수 있습니다.

**AgentCore Identity가 사용자 토큰을 검증하고 워크로드 액세스 토큰 발급** — AgentCore Identity는 사용자 토큰의 서명, 만료 시간, 발급자, 대상 및 scope를 검증한 다음 워크로드 액세스 토큰을 반환합니다. 이를 통해 신뢰 체인을 유지하면서 다운스트림 리소스에 안전하고 감사 가능한 방식으로 액세스할 수 있습니다. AgentCore Identity는 에이전트 ID 확인, 사용자의 원본 OAuth/OIDC 토큰 서명 및 claim 검증, 에이전트가 사용자를 대신해 요청된 리소스에 액세스할 권한이 있는지 확인하는 등 요청에 대해 포괄적인 제로 트러스트 검증을 수행합니다. 이 검증은 출처나 이전 신뢰 관계와 관계없이 이루어지므로 모든 요청이 독립적으로 인증되고 권한을 부여받습니다.

**AI 에이전트 애플리케이션이 에이전트 호출** — 에이전트 애플리케이션은 워크로드 액세스 토큰을 받고 요청된 작업을 실행하기 시작합니다. 이제 에이전트는 자신의 ID와 자신이 대신하는 사용자의 ID에 대한 검증 가능한 증명을 바탕으로 작동할 수 있습니다. 따라서 원래 사용자까지 작업의 전체 추적성을 유지하면서 여러 도구와 리소스에 인증된 요청을 보낼 수 있습니다.

**에이전트가 리소스 액세스 토큰 요청** — 에이전트가 AWS 리소스 및 서드 파티 서비스(예: Google Calendar, Slack 또는 내부 API)에 액세스해야 할 때 AgentCore Credential Provider에 적절한 자격 증명을 요청합니다. 에이전트는 자신의 ID 및 권한 부여를 증명하는 워크로드 액세스 토큰을 제시합니다. 시스템은 이 토큰을 검증하고 구성된 정책과 사용자 동의를 기반으로 에이전트가 액세스할 수 있는 리소스를 결정합니다. AgentCore Identity에 요청된 사용자 ID와 리소스에 대한 기존 토큰이 있다면 리소스 액세스 토큰을 반환합니다.

**Amazon Bedrock AgentCore Identity가 리소스에 대한 사용자 인증 요청** — AgentCore Identity의 토큰 볼트에 요청된 리소스의 기존 액세스 토큰이 없다면, 제공된 URL에서 사용자 동의가 필요하다는 응답을 반환합니다. 명시적인 사용자 동의가 필요한 리소스(예: Google Calendar 같은 서드 파티 서비스)의 경우 시스템에서 사용자 인증 흐름을 시작해야 할 수 있습니다. 일반적으로 사용자를 리소스 공급자의 권한 부여 서버(예: Google의 OAuth 2.0 엔드포인트 또는 Microsoft의 Azure AD)로 리디렉션하여 에이전트가 사용자의 데이터에 액세스할 권한을 부여하도록 합니다. 이 단계에서는 에이전트가 사용자를 대신해 액세스할 수 있는 리소스를 사용자가 계속 제어할 수 있도록 하며, OAuth 2.0 client credentials grant(machine-to-machine) 및 OAuth 2.0 authorization code grant(사용자 위임 액세스) 흐름을 모두 지원합니다.

**Bedrock AgentCore가 사용자 인증 요청** — 에이전트 서비스는 요청된 권한 부여 URL을 사용자용 애플리케이션에 응답으로 전달합니다.

**사용자용 애플리케이션이 인증 및 동의 요청 표시** — 사용자에게 자격 증명을 입력하고 에이전트와 데이터를 공유할지 묻는 메시지가 표시됩니다.

**사용자가 데이터 공유에 동의** — 사용자가 서드 파티 공급자의 동의 요청을 수락합니다.

**서드 파티 리소스가 사용자 자격 증명을 검증하고 리소스 액세스 토큰 발급** — 서드 파티 서비스 공급자(예: Google, Microsoft 또는 Salesforce)는 사용자의 자격 증명과 동의를 검증한 다음, 에이전트가 사용하도록 지정된 액세스 토큰을 발급합니다. 이 토큰의 scope는 일반적으로 최소 권한 원칙에 따라 사용자가 에이전트에 명시적으로 부여한 권한으로만 제한됩니다. 이 권한 부여 요청의 콜백 URL은 공급자의 응답을 처리하고 요청된 리소스의 액세스 토큰을 수집하는 AgentCore Identity 서비스 엔드포인트입니다.

**AgentCore Identity가 리소스 액세스 토큰을 저장하고 반환** — AgentCore Identity는 에이전트의 요청에 대한 응답으로 리소스 액세스 토큰을 반환합니다. 또한 나중에 사용할 수 있도록 리소스 액세스 토큰을 토큰 볼트에 안전하게 저장하고, 특정 에이전트 ID와 사용자 ID 조합에 연결합니다. 이를 통해 이후 요청에서 사용자 인증을 반복하지 않고 토큰을 재사용할 수 있어 보안을 유지하면서 사용자 경험을 개선합니다. 토큰은 무단 검색을 방지하도록 암호화되고 액세스가 제어됩니다. 토큰 볼트는 제로 트러스트 원칙에 따라 작동하므로 자격 증명을 처음 획득한 정확한 에이전트와 사용자 조합만 액세스할 수 있습니다. 따라서 서로 다른 에이전트나 사용자 간의 무단 교차 액세스를 방지합니다.

**에이전트가 리소스에 데이터 요청** — 에이전트는 리소스별 액세스 토큰을 사용하여 서드 파티 리소스의 데이터를 읽거나 쓰는 API 호출을 수행합니다. 에이전트는 사용자가 부여한 권한과 리소스 공급자 API가 정의한 기능의 범위 안에서 작동합니다. 감사 및 보안을 위해 에이전트 ID가 명확히 설정된 상태에서 모든 작업을 수행합니다.

**서드 파티 리소스가 리소스 액세스 토큰을 검증하고 데이터 반환** — 서드 파티 서비스는 에이전트가 제공한 액세스 토큰이 유효하고 만료되지 않았으며 요청된 작업에 필요한 scope가 있는지 검증합니다. 검증에 성공하면 리소스는 요청된 데이터를 반환하거나 요청된 작업의 완료를 확인합니다. 이 검증을 통해 적절한 사용자 동의를 받은 권한 있는 에이전트만 보호된 리소스에 액세스할 수 있습니다.

**AI 에이전트 애플리케이션이 응답 구성** — 에이전트는 AWS 리소스와 서드 파티 서비스에서 받은 데이터를 처리하고 추가 로직 및 컨텍스트와 결합하여 포괄적인 응답을 생성합니다. 에이전트는 사용자의 원래 요청에 대한 컨텍스트를 유지하며, 액세스한 리소스의 데이터를 반영하면서 응답이 사용자의 요구 사항을 충족하도록 합니다.

**AgentCore가 애플리케이션에 응답 반환** — 에이전트는 완성된 응답을 사용자용 애플리케이션에 다시 보냅니다. 이 응답에는 에이전트 작업의 결과, AWS 리소스와 서드 파티 서비스에서 검색한 데이터 및 완료된 작업의 확인 정보가 포함됩니다. 응답은 보안 컨텍스트를 유지하며 사용자를 대신해 수행된 작업에 대한 감사 정보를 제공합니다.

**사용자용 애플리케이션이 응답 표시** — 애플리케이션은 텍스트, 구조화된 데이터 또는 완료된 작업 확인과 같은 적절한 형식으로 에이전트의 응답을 사용자에게 제공합니다. 사용자는 요청 결과를 확인하고 에이전트가 여러 리소스에 대한 승인된 액세스를 사용해 수행한 작업을 이해할 수 있습니다.

**프로세스 완료(Done)** — 모든 토큰이 적절히 관리되고 감사 로그가 기록되며 사용자 요청이 처리되면 워크플로가 종료됩니다. 시스템은 전체 프로세스에서 보안을 유지하면서, AI 에이전트를 활용해 여러 서비스와 플랫폼의 데이터에 액세스하고 조작하려는 사용자에게 원활한 경험을 제공합니다.

이 워크플로는 AgentCore Credential Provider를 기존 인증 방식과 구분하는 몇 가지 핵심 기술 원칙을 기반으로 합니다. 이 서비스는 요청의 출처나 이전 신뢰 관계와 관계없이 모든 요청을 검증하는 제로 트러스트 보안을 구현합니다. 가장이 아닌 위임 기반 인증을 사용하여 에이전트가 사용자 컨텍스트를 포함한 상태에서도 항상 에이전트 자신을 인증하도록 합니다. 또한 MCP(Model Context Protocol)를 준수하며 에이전트와 도구 간 통신을 위한 표준 프로토콜을 지원합니다. 마지막으로 크로스 플랫폼을 지원하므로 일관된 보안 표준을 유지하면서 AWS, 다른 클라우드 공급자 및 온프레미스 환경 전반에서 에이전트를 운영할 수 있습니다.
